# Design System: ADE

## Overview

**Creative North Star: "The Interchange"**

Every piece of work is a line on a metro diagram. Stations are stages (or, in the Worktrees page, a repo's worktrees), the current stage is the train, and who must act next is printed beside it. The world lends ADE exactly four things: line inks, a glyph vocabulary, a dense one‑cell rhythm, and the station line as its signature move. Layout, navigation, and controls stay standard terminal conventions (`j/k`, `enter`, `esc`, `?`, overlays).

ADE paints no background and chooses no font. It inherits the user's terminal ground, foreground, and typeface, in dark and light themes alike, and it keeps working under `NO_COLOR`, because glyphs carry every state.

**Mode and audience:** Operate. A terminal-first developer starting or resuming the day; the job is to see what needs them next, start or resume work, and read what changed. It runs in any terminal, including VS Code's and browser terminals. The design refuses the category default of a status-word column in a bordered-pane table. Every state shows its evidence, guide words head every list, colour stays quarantined to tracks and marks, and columns sit on whole-cell widths and reflow by whole columns, never truncating mid-word without an ellipsis.

**Key Characteristics:**

- The terminal's own ground, ink, and font. Colour appears only as line inks and state marks.
- A glyph vocabulary is the icon system, with an ASCII fallback (`host.glyphs = "ascii"`).
- **The glyph set is the whole chrome, not just the marks.** `glyphs` (`internal/tui/theme.go`, mirrored in `internal/overview/theme.go`) holds the state marks, the connectors, the ellipsis (`…`/`...`), the pane separator `Pane` (` │ `/` | `), the faint station connector `Thin`, the palette `Prompt` (`›`/`>`) and input `Cursor`, and the overlay `Border` (rounded box; in ascii `+ - |` with `+` corners). Dialogs, pop‑ups, help and the drawer take their border from `g.Border`, never `lipgloss.RoundedBorder()`. Literal UI text that carries `·`, `→`, `←`, `–` or `…` goes through `g.T(...)`, which maps them to `-`, `->`, `<-`, `-` and `...` in ascii and is the identity in unicode; the same call wraps text generated by other packages (plan steps, totals, court reasons) at the point it is drawn. User and forge text is never passed through it. Under `host.glyphs = "ascii"` the whole dashboard is 7‑bit ASCII apart from that user data; `TestAsciiGlyphSetDrawsOnlyASCII` (tui) and `TestAsciiPaneDrawsOnlyASCII` (overview) render every page, dialog and pop‑up and fail on any other rune. A new hard‑coded glyph needs a field in `glyphs` or a `g.T` call.
- Bold for what is selected or needs you; faint (SGR 2) for metadata.
- Section rules carry guide words (`2 repos · 3 trees · updated 8s ago`).
- Overlays (dialog, drawer) are the only bordered surfaces.

## Colors

The base is the user's own terminal palette. ADE adds line inks, one per repo, and three state marks.

### Primary (line inks)

These are assigned per repo by a stable hash of the repo name, so the same repo keeps its colour across projects and sessions:

- **Line Scarlet** (#e0453a)
- **Line Cobalt** (#3b7dd8)
- **Line Amber** (#e8a33d)
- **Line Green** (#3fa66b)
- **Line Violet** (#b05fd0)
- **Line Teal** (#2bb3b3)

Inks colour a repo's stations and its branch connectors, and nothing else.

### Secondary (state marks)

- **Warn Amber** (#e8a33d): uncommitted changes, behind or diverged trees, skipped pulls, warning severity.
- **OK Green** (#3fa66b): success severity marks.
- **Failed Red** (#e0453a): failures, failed fetches, error severity.

### Neutral

- **Terminal foreground / background**: all text and ground, inherited.
- **Overlay Rule** (#666666): the rounded border of dialogs and the drawer.

### Named Rules

**The Quarantine Rule.** Colour lives only in line inks and state marks. Every other character is terminal ink: bold, normal, or faint.

**The Evidence Rule.** No state is colour alone. Each carries a glyph and a word (`✎ uncommitted`, `↓2 behind`, `▲` with a title), so `NO_COLOR` loses no meaning.

## Typography

**Font:** the terminal's own monospace face. ADE never sets or assumes a font.

**Character:** one face at one size. Hierarchy comes only from weight (bold), intensity (faint), and position.

### Hierarchy

- **Emphasis** (bold): the product mark `ADE`, project names in section rules, the selected row's label, the preview title, overlay titles, key names in hints.
- **Body** (normal): tree names, values, toast text, unread inbox titles (bold) vs read ones (normal).
- **Metadata** (faint): guide words, status words that need no action (`up to date`), timestamps, kinds, key descriptions.

### Named Rules

**The No‑Mid‑Word Rule.** Anything cut to fit ends in `…`. Prose that cannot be cut wraps instead.

## Layout

- **Two‑pane, ≥ 100 columns:**
  - header line, blank line
  - list at 64% of the width, then ` │ `, then the preview pane (one cell of right margin)
  - footer line
- **Three‑region, ≥ 140 columns (Home):** list, preview and a 28‑cell rail with Activity and Services (see Three regions).
- **Single‑pane, < 100 columns:** the list fills the width. `tab` swaps it for the selected tree's details. Overlays become full‑width.
- **Fixed rhythm:** every row is one line. Repo names sit in a 10‑cell column; branch stations indent under their repo with `┣━`/`┗━`. Statuses are right‑aligned. Sections are separated by one blank line.
- **Scrolling:** the list scrolls so the selected row always stays visible.
- **Header:**
  - left: scope (`ADE · 2 projects · 4 repos`)
  - centre: activity (`⟳ updating 3/4` / `⟳ syncing` only while work runs; idle is plain faint `synced 40s ago`; a warning shows its severity glyph and title)
  - right: the AI chip, then the unread count. The chip is `AI $0.38 / $2.00 day`: spend against the cap of the budget period nearest its cap (day, week or sprint), faint while there is room; amber with `▲` from 80% (`▲ AI $1.70 / $2.00 day`); red with `✕` and the word `cap` at the cap. With no cap set it is just `AI $0.38`; with `ai.mode = "off"`, a faint `AI off`; with no AI profile configured, nothing. It is read from the ledger off the UI loop, so the header never waits on it.
- **Footer:** a toast when there is one, otherwise key hints.
- **Worktrees preview:** a long `path` is cut from the left (`…/demo-gl/api/main`) at a separator, so repo and tree stay visible.
- **Help (`?`):** a blank‑field dialog (nothing of the page shows around it, the way every dialog sits) listing every Home and Worktrees key under Move, Selected item, Pages and Leave section rules, one key per row. On a terminal too short for that it tightens to paired keys (`s M  start work; create the MR for started work`) so the whole list still fits; no description is cut mid‑word. Toasts are held back while it is open.
- **Station legend:** the `as st br dr ci rv mg` row appears once, above the first project that has tracks, never above a project whose sync failed.

## Elevation & Depth

The base layer is flat. Depth is one step: overlays composite above the screen. The help dialog is centred; the inbox drawer is right‑aligned and full height. There are no shadows. Overlays occlude what is beneath them completely.

## Shapes

- **Borders:** rounded box‑drawing borders (`╭╮╰╯`), only on overlays.
- **Rules:** section dividers are a single horizontal rule (`─`) between the title and the guide words.
- **Vertical line:** `┃`/`│` marks a line in previews and dialogs (the metro line seen side‑on).

## Components

### Section rule

` <project> ──────── <guide words>`. Bold title, faint rule, faint guide words, right‑aligned.

### Tree line (signature)

- **Columns:** marker (`▸` when selected), repo name (first row of a repo only), station, label, then the right‑aligned status.
- **Stations:**
  - a baseline is `●` in the repo ink
  - a work branch is `┣━◉` (or `┗━◉` for a repo's last branch), with the connector and train in the repo ink
  - a missing repo is a faint `○` with `not cloned · U to update`
- **Status:** `up to date` (faint), `↑n to push`, `↓n behind` (amber), `↑a ↓b diverged` (amber), `no upstream` (faint), plus `✎ uncommitted` (amber), joined by ` · `.

### Preview pane

- **Title:** a bold `project / repo / tree`, then a faint kind line.
- **Key/value block:** faint 10‑cell keys.
- **`Last update`:** this repo's failures and skips, if any.
- **`Recent`:** up to eight inbox rows: severity glyph, title (bold if unread), and a right‑aligned faint age.

### Work item row (Home, signature)

One line per item:

- **Columns:** marker (`▸` when selected), short ref (`#1`, or `api!3` outside the tracker; the column is as wide as the longest ref), title, an unread marker (bold amber `new`, or `3 new`) when notifications about the item are unread, then the track, weight (`5w`, or a faint `–` when unweighted, never `0`), and court · reason. The unread marker is a word because dots are stations on this screen.
- **Legend:** one faint line under the first project rule names the stations above their columns (`as st br dr ci rv mg`; initials when the track is compact).
- **Track:** seven stations (assigned, started, branch, draft, ci, review, merged) joined by `━━` (travelled, in the item's line ink) and `──` (to come, faint). Below 110 columns the connectors shorten to one cell (`●━●━◉─○─○─○─○`) so titles keep their room.
  - Done stations are `●`; the current one is the train `◉` in the line ink (bold).
  - The train is `◎` when the item spans repos, and warn amber when the item is blocked.
  - A done item is a fully travelled line.
  - An item missing both type and app shows a faint `? untriaged` (`? triage` when compact) instead of a track.
- **Court:** `you` is bold with a normal‑ink reason; `blocked` and `waits` are amber, bold and lead with the warn glyph (`▲ blocked`, `! blocked` in ascii) so they carry emphasis without colour; all other courts are faint. The column is as wide as the longest court text (capped at 40, or two fifths of a narrow list); a reason that still doesn't fit is cut at a word boundary with `…`, never mid‑word.
- **Done but kept open:** an open tracker carrying the manifest's `labels.workflow.done` value is done (hidden from rows, counted in done weight); a merged item without it reads `you · set workflow::done`.
- **Sections:**
  - Each project starts with a section rule: `<project> · <sprint>`, then guide words in priority order: end date and workdays left (amber at ≤ 1), weight load (`20w committed · 2w done · 2 unweighted`, or `no weights`), the next sprint. When the full guide doesn't fit, the sprint and load squeeze into one compact group (`ends Fri 13 Nov · 3d left · 2/20w`, done/committed) before any group is dropped; lower‑priority groups then drop whole. Sync age lives only in the header.
  - Sub‑rules are indented three cells: My work, Reviews requested, Sprint · open, Next sprint, Previous sprint (only while the window has one: `2 unfinished · carried over from Sprint 41`, unfinished items of that sprint not already under My work), Open MRs · search (only while a search matches open MRs on the forge), and last, Activity.
  - **Load guide words:** `20w committed · 2w done · 18w left · 2 unweighted · your avg 8w`. `left` is committed minus done weight; `your avg` is your own per‑sprint average over the last three closed sprints (issues assigned to you only), read from the forge off the UI loop after each sync, so it appears a moment after the rest; with no closed sprint it is absent. Narrow rules shed `unweighted`, then the average, then fall back to the compact group.
- **Badge column:** after the track, `✉ 2 ✓`: unresolved review threads over the item's open MRs (`✉` plus a number, `m 2` in ascii; blank at zero) and the newest pipeline as one glyph (`✓` green, `✕` red, `⟳` running; `+`, `x`, `~` in ascii). It is six cells; it is dropped when keeping it would leave the title under 20 cells, so a narrow list keeps its titles.
- **Epic:** when the title cell has room (36 cells or more), the epic follows the title in faint, ` · Exports`, taking at most a third of the cell; the title is cut first.

### Search, palette, filter picker, Activity (Home)

- **Search (`/`):** a bar replaces nothing: it is the first line of the list, `/ text▏` on the left and `n matches` on the right (`⟳ searching open MRs · ` before the count while the forge answers; a red `✕ MR search failed` if it cannot). Every word must match within one field of the row, case‑insensitively: as a substring or, from three letters, as letters in order close together (`rte` finds `Rate`); the fields are ref, title, type, apps, workflow, epic, reason and court (an MR: ref, title, author, branch). The list narrows as you type. After a 350 ms pause the project's open MRs are listed off the UI loop, once per search; those that are not already review requests show in the section `Open MRs · search`. `enter` keeps the filter and gives the keys back to the list, `esc` clears it (the footer shows `enter keep filter · up/down move · esc clear search` while typing).
- **Palette (`:`) and filter picker (`f`):** one dialog, a rounded box at the shared top row, at most 100 columns, blank field around it. A `:` (or `›` for the picker) input line, then at most ten entries, best match first: the name, a faint key and a faint CLI equivalent (`Standup  ade standup`), the selected one led by `▸` and bold, the active filter marked `✓`. Keys: type to narrow, `up/down` (`ctrl+n/p`, `tab`) choose, `enter` runs, `esc` closes. Every key action of Home is an entry, plus pages, filters (`Filter: type bug`) and projects (`Project: demo`). Actions that need a Home row are not offered on other pages. Toasts are held back while it is open.
- **Palette on the MR page and Worktrees:** `:` opens the same dialog there. On the MR page the entries are every action of its help: the six tabs, next/previous tab and MR, back, move, copy link, reload, approve, ready/draft, merge, submit, agents (`P`), and per tab the thread, diff, review and CI actions (`Threads: reply`, `Review: accept the draft`, `CI: retry the pipeline`), plus the AI ones while AI is on. A tab's entry switches to its tab and then presses the key, so it does what the key does there. On Worktrees it adds `w`, `W`, `v` and `y`. Every key listed in a page's help has an entry (a test holds this), so a web tty that eats keys still reaches everything by name.
- **Filter (`f`):** the picker lists `all`, `waiting on you`, `needs triage`, `blocked`, `label drift`, then every `type`, `app` and `workflow` value present on Home. The footer names the active one (`filter: type bug`), with the project after a `·` when `p` has chosen one.
- **Activity:** the newest inbox events (severity glyph, age as `now`/`5m`/`3h`/`2d`, title; read rows faint) scoped to the project filter. Below 140 columns it is the last sub‑rule of the list, collapsed to its rule (`Activity ─── 3 recent · e shows`) until `e`; at 140 columns and wider it is the rail's top block and always open.

### Three regions (≥ 140 columns)

List, ` │ `, preview, ` │ `, rail. The rail is 28 cells wide: Activity (up to eight events) above, then Services of the selected item, one service per line (the same glyph plus word or port as the strip), attention first. The preview is 30% of the rest (at least 34 cells) and no longer carries the services strip. Between 100 and 139 columns the two‑pane layout stays; below 100 the single pane.

### Item preview

- **Header:** a bold `ref  title`, then a faint meta line (type · apps · sprint · weight or "unweighted").
- **Workflow label:** a faint `label in review ✓`, or an amber `▲ label in review · stage says in progress` when they drift.
- **Station list:** the item's line drawn vertically, `┃` in its ink where travelled and a faint `│` ahead. Each station carries its evidence: assignee, child issue, branch, MR and state, pipeline, approvals and unresolved threads, merge date.
- **Below the stations:** the court line, then the Services strip when any of the item's workspaces runs something, an amber `▲ needs …` when triage is missing, the task count, and the first eight lines of the description rendered as markdown (see Markdown and code below; a cut ends in a faint `…`).
- **Services strip:** one faint-labelled line, `services  api.dev ● 54031 (feature tree) · web.dev ● 54044`, wrapped to the pane. Every state is a glyph plus a word or number: `●` and the port when ready, `○ starting`, `✕ stopped` (it was running and its process is gone), `✕ failed` (it died before it became ready), `▲ blocked by api.dev` (it still runs but a requirement died) (ascii `*`, `o`, `x`, `!`). `(feature tree)` marks an instance running from a feature worktree rather than the repo's baseline; `(shared)` marks one held by more than one worktree's workspace, and it shows under every item that holds it. Chips that need a look come first (failed, blocked, stopped, starting) and a ready chip never shares their line; long strips wrap between instances, never inside one. Tags merge into one parenthetical: `(feature tree, shared)`. Nothing is drawn when no workspace of the item runs anything; it refreshes every two seconds.

### Pop‑ups

- **Shape and position:** a stack in the bottom‑right corner, a third of the width (44–64 cells; full width below 100 columns), up to three visible. A faint `+n earlier · esc dismisses all` line sits above them when more are waiting.
- **Each pop‑up:** a rounded box whose border is the severity colour (failed red, warn amber, ok green, overlay grey for info). It shows the severity glyph and title, then a faint line with what it is about (`ade-demo-env/api!1`) and, for failures, `esc dismiss`. The dotted event id (`mr.load.failed`) belongs to the inbox and the audit log, never to the pop‑up.
- **Lifetime:** non‑failures expire after 6 s; failures stay until `esc`. Every pop-up wraps its title and subject (up to five lines each) so the end, which is often the instruction, is never cut; a command is kept on a line of its own after the cause (`port 37007 is already in use` / `free the port, then run ade ws up`).
- **Under a dialog:** while the Start work, Agent, Notes, Weight, Sprint-move or an MR page dialog (or its help) is open, pop‑ups are held back (they stay queued and show when it closes), so they never cover its key row.
- **Transient events** (for example a no‑op update) only pop up and are never recorded.
- **Other processes:** rows recorded by other ade processes while the dashboard is open pop up once. The task runner (`ade task run`, `ade ws up`) reports this way: `task.ready` and `task.done` are green, `task.blocked` and `task.exited` amber and, like failures, stay until `esc`, `task.failed` red (stays until `esc`), `task.exited` amber. Titles say what happened in a few words (`api.dev failed to start`, `web.dev waits for api.dev`); the line beneath says what is new: the tree a ready node runs in (`api/1-rate-limit`), or the cause and the way out (`port 37007 is already in use`, then `free the port, then run ade ws up` on the next line). The raw error and the log path go to the notification centre's detail.
- **Workspace key (`w`):** a success pops up `opened workspace api/418-limit` (transient); a missing `ade` zellij session is an amber transient hint, `workspace not opened: no ade session`, with `start ADE with ade, then press w` on the subject line; on a host that cannot open a tab (a plain terminal) the pop-up reads `api/main: no tab on this host` / `command copied, paste it in a shell` and the full `cd … && ade ws up --no-zellij` command goes to the clipboard (OSC 52) instead of being wrapped in the box; any other failure is a red pop-up that stays.
- **VS Code workspace key (`v`):** writes the multi-root `.code-workspace` of the selected item (an MR row uses its item, else its tree; on Worktrees the tree under the cursor) and opens it when `code` is on PATH. A success pops up `VS Code workspace: <path>` (transient); without `code` the same pop-up is amber with `code is not on PATH: open <path> in VS Code` on the subject; a failure is a red pop-up that stays. The palette lists it as `VS Code workspace for <ref>`; the help overlay carries it beside `w`. The footer is unchanged.

### Notification centre

- **Shape:** a rounded overlay, 60 cells wide (full width when narrow), right‑aligned, full height.
- **Title line:** `Notifications · n unread · showing <filter>`.
- **Rows:** severity glyph, title (bold if unread), and age, with a faint `kind · subject` beneath. The selected row expands up to four lines of detail behind a faint `┃`. The empty state explains what will land there.
- **Keys:** `enter` goes to the subject and marks it read, `f` cycles the filter (all / unread / problems), `r`/`R` mark read, `esc` closes. While the centre is open the footer shows these keys instead of the page's.

### Help dialog

A rounded, centred overlay. Each key row starts with a faint `┃`, then the bold key in a 7‑cell column, then the description.

### Start work dialog (`s`, `M` on a Home row)

A blank field that replaces the body (the Agent dialog's mechanism): a rounded box at a fixed top row, at most 100 columns wide and centred (full width below), so no list or preview shows around it and it does not move between screens. It walks the PLAN 6.3 flow in two screens. It opens at once and reads the issue, manifest and forge in a command; the list beneath never waits on the network.

- **Choose.** Three section rules with guide words:
  - `Repos` (`app::api routes here`): one row per manifest repo, `[x]`/`[ ]` and the repo name in its line ink, then the forge path in faint. The repos the app labels route to are pre‑selected, and a repo that a chosen one `requires` (web requires api) carries a faint `web requires api: also a child here?`. The tracker project is a last, faint row (`work lives in the tracker project`).
  - `What to create`: three radio rows, `●` chosen and `○` not (`*` and `o` in ascii): Draft MR, Branch only, Browse, each with a faint line of what it writes.
  - `Child issue` (`conventions.child_issue`): auto, always, never, same radio form.
  - `Main pane` is one faint row under the rules, not a section: `Main pane  ● editor  ○ omp  ○ shell  a toggles · <what it is>`, the radio form again. It starts on `host.layout`, else the manifest workspace's layout, and rides along as the tab's layout.
  - Keys: `j/k` move, `space` selects, `m` and `c` cycle mode and child policy, `a` the main pane, `enter` continues, `esc` cancels.
- **Confirm.** `Confirm` with the count of forge writes and local steps in its guide (`9 forge writes · 2 local steps`; `no forge writes` for Browse; `nothing to create: everything exists` on a re‑run). Each repo is a station line in its ink, `●━ api ade-demo-env/api`, with its steps hanging off it on `┣━`/`┗━` connectors. Every step carries a glyph‑and‑word mark: bold `+ forge` for a forge write, `+ local` for git and the workspace tab (the guide counts exactly these rows), a faint `✓ exists` for what is already there. The workflow label move hangs under the stations on a faint `┃`. When the item spans repos the lines meet at the tracker item: an interchange `◎ tracker#8 the lines of api and web meet here` (`%` in ascii) opens the list and each repo hangs from it on `┣━●`/`┗━●`, its steps indented beneath. Before the child exists its number and reference are words, never `?`: the branch reads `<child iid>-retry-failed-webhook-deliveries`.
- **MR block** (Draft MR mode): a section rule `MR · api` with the template name, the body exactly as it will be sent behind a faint `┃` (`Closes <child issue, created first>` until the child has a number), then `Quick actions` with one row each: bold `keep` or faint `strip`, the plain‑words summary (`request review from @reviewer-rae`), and the template line in faint. `x` toggles the action under the cursor, `X` all of them, `e` edits the body in `$EDITOR` (the dialog is suspended meanwhile) and `E` edits it in the dialog itself (the hint reads `e/E edit body`; a bubbles textarea in place of the MR block under a `MR body · api  editing` rule: `enter` is a newline, `alt+←/→` move by word, a paste keeps its newlines, `ctrl+s` keeps the text, `esc` drops it); an edited body is sent as written and the toggles stop applying, `t` cycles templates, `p` switches repo, `l` confirms the workflow move when `labels.workflow.sync = ask`. When the terminal is short the confirm keeps its keys on screen: each repo's step list collapses to one line (`┗━ + forge child issue, link, branch, draft MR · + local worktree, workspace`) before the body is touched; then the body loses its blank lines, then the spacer rows from the bottom up (the ones above the keys and a warning first, so the gaps above the section rules go last), and what still does not fit is clipped with a faint `┃ … 14 more lines` (`e` shows all of it). It folds away entirely only when the terminal is too short for two lines of it. Stripping only changes this MR, never the template in the repo.
- **Done.** One row per step with `✓ created`, a faint `· exists`, an amber `▲ skipped` or a red `✕ failed`, naming what was produced (`child issue api#3`); under it a faint `┃` line per repo with child, MR and worktree. An amber note under the rows (`▲ workspace not opened:`) puts its recovery command on its own lines, wrapped at path separators so none of it is cut. A failure keeps the rows that succeeded and says `s resumes where it stopped`.
- `M` opens the same dialog on its confirm screen with only the MR step (the branch must exist; it says so when there is nothing to create).
- While the dialog is open it owns the keys (`q` closes it, it does not quit). Under `NO_COLOR` and the ascii glyph set every state still reads from its word and glyph.

### Classify dialog (`c` on a Home row)

A rounded, centred overlay (full width below 100 columns) in the shape of the Start work dialog, for PLAN 3's "needs triage" items. It opens at once and reads the issue, manifest and suggestion in commands.

- **Suggested labels.** One section rule whose guide words say where the proposal came from: `keywords · AI is off or not configured · no cost`, or `AI · <model> · $0.0010` (`cached, $0` on a repeat). One row per label, `●` ticked and `○` not (`*` and `o` in ascii), the ticked name bold; then a faint `why:` line and a faint `ignored …` line for anything the model proposed outside the team's values. The keyword classifier says what it could not find in the `why:` line (`…point at bug; no app keyword matched`), so a facet left out is never silent. A faint footer names the facets still without a suggestion (`no app label suggested · labels are only added, never removed`; just the second half when every missing facet is covered).
- **Suggested weight.** For an unweighted issue a second section rule, `Suggested weight ── from similar closed issues · no model`, with the value in bold (`3w`) and a faint line of how it was derived: the lower median of the weights of closed issues of the same type and app that share a title word (plurals folded), by ref. It is the same with AI on or off and never costs anything. Without anything comparable a faint line says why. An item whose only open point is its weight skips the label section; `=` hands the value to the Weight dialog, where it is shown as a write before anything happens.
- **Keys.** `j/k` move, `space` or `x` ticks, `enter` adds the ticked labels (nothing ticked: an amber `▲` line says so and the dialog stays), `esc` closes without any write. Adding the labels refreshes Home from the forge only; it never starts a git update.
- **Pre-flight.** When `ai.mode = "ask"` and the estimate passes the ask-first amount, the dialog first shows an amber `▲ this asks the model first` line, then the profile, model, role, token estimate, price and destination as faint fields laid out under it with a two-cell hanging indent (a wrapped line never starts with a bare `·`), then the amber reason (`▲ estimated $0.0010 is over the $0.0001 you set to be asked first`). No config key appears in the text; `y` sends, `esc` cancels.
- **Done / nothing to do.** `✓ added type::bug`, closed with `enter`; an item that already has both facets says so in a green `✓` line and that no model call was made.
- **Failure.** A red `✕ <cause>` and a faint line of what to do: `✕ omp is not installed` / `install it or set ai.mode = off`; a spending cap or the provider's budget (`the Budget page shows the caps`); an unusable model answer or a timeout (`try again`); a forge that could not be read or written (`check the connection and press c again`, `try again, or add them on the forge`). The raw error (an exec message, an HTTP body) is never on screen; every failure is in the audit log (`ai.classify` with outcome error), where the Log page shows it whole.

### Notes dialog (`n` on a Home row)

The shared dialog shape (rounded, ≤ 100 columns, top-anchored on a blank field, full width below 100; the toasts are held while it is open). The item's title in faint, then a `Notes` section rule whose guide words say `yours · ADE never rewrites them`, then the text under `## Notes` in the item's record, wrapped, behind no decoration: it is the user's prose. Digits type, `backspace` deletes, `+`/`-` step (never below 1), `n` clears the weight. After: `✓ done` per written issue, `● unchanged` for one already there, `✕ failed` with the recovery line, and a faint `ADE moves issues only: the project lead closes them.` Home refreshes from the forge; the Sprint review page reloads.

The footer names `J/K`, `>` and `M`.

### MR page (`enter` on a Home row)

Opens the MR of the selected item (the first open one; `[` `]` switch when the item has several), or the MR of a review request. `esc` goes back to Home; inside a thread (narrow) or the diff pane it first goes one step back. Data is read when a tab is first shown and kept per MR for the session, so reopening is instant; `U` reloads it.

- **Head, four lines:** the bold `#1 › api!1  title` (faint item ref, then the MR); a **status strip** (`Ready · ✓ CI passed · 1 of 2 approvals · 2 unresolved · ✓ mergeable`, with a spinner and the action word, `⠋ merging…`, in front while a write runs); the tab bar (`[Threads 2]` bold in brackets, others faint, a count or CI glyph as badge); then the tab's section rule, its guide words on the right. Under pressure the strip drops its lowest-priority segments whole, merge verdict first.
- **Tabs:** Overview, Threads, Diff, Review, CI, History (`tab`, `shift+tab`, `1`–`6`). An item with no MR yet opens on Overview (with its station list) and History only.
- **History:** the audit entries recorded against this MR and its work item, newest first, one line each (`12m ago ✓ forge thread resolve … ok`), read when the tab is first shown and again after each write. A faint `+n earlier · ade audit shows them all` closes a long list.
- **Overview:** the item's station list (as in the Home preview), then a key/value block for the MR (faint 10‑cell keys: state, author, branch, reviewers, approvals, pipeline, threads, merge) and the description (rendered as markdown, in full, wrapped to the pane). Scrolls. With AI on, a `Summary` sub‑rule sits where the description was, guide words `AI · claude-haiku-4-5 · $0.0021` (`cached, $0` on a repeat, `· includes your notes` when notes went in), the summary (markdown too) under it and a faint line `d shows the raw description · s asks again`. `d` swaps in the raw description (sub‑rule `Description`, guide `d shows the AI summary`); `s` buys a new summary past the cache. The summary starts by itself once the MR and its diff are read and never blocks the page: while it runs the description shows with `Summary ── AI · asking the model` and a spinner above it; when the pre‑flight needs a yes (ai.mode ask) it says `▲ <why> · s asks · nothing was sent`; a budget stop or a missing model reads `▲ no summary: budget stop: …`. With `ai.mode = off` (or no profile) there is no Summary, no `d`, no `s`: the description is all there is.
- **Threads:** list left (5/12 of the width), conversation right; below 100 columns one pane (`enter` opens the conversation, `esc` closes it). Sub‑rules `Unresolved (2)`, `Comments (1)`, `Resolved (5)`; a row is the marker, `● open` (amber) / `✓ done` (faint) / `note`, `path:line` (`general` without a position), the quoted first line and the author. The conversation shows the position, the diff lines around it (the thread's line bold), then each note under a bold author and a faint age. A long conversation shows its latest notes.
- **Diff:** file list left (a third of the width, 30–44 cells), diff right. Each file is `R limit/{bucket.go → token_bucket.go}  +5 -1 ✎2`: a one-letter status (A added, M modified, R renamed, D deleted; the legend is in the rule's guide words), the shared directory outside the braces of a rename, counts, and `✎n` for your drafts. When the column is tight the name that says what the change is survives and `✎n` never moves: a rename drops its directory (`{bucket.go → token_bucket.go}`), then the old name (`→ token_bucket.go`), a plain path loses its directory from the left (`…/limit/bucket.go`). Below 100 columns the list and the diff take turns; `enter` opens a file, `h` returns. A diff line is the cursor marker, the old and new number (faint, four cells each: a removed line has only the old, an added line only the new), then the mark `+`/`-`/space (green bold for added, red bold for removed) and the text, syntax-highlighted by the file's extension (see Markdown and code; a file with no known language keeps the whole line in the mark's ink); long lines end in `…`. Non‑adjacent hunks are separated by a faint `┃ ───`. Drafts and existing threads sit under their line behind a faint `┃`.
- **Loading and errors:** a tab that has not been read shows `⠋ reading the diff…`, and its rule makes no claim about what it has not read (CI says `pipeline #9001` until the jobs arrive, then `· 2 jobs`); the status strip says `⠋ reading from the forge` on the first read of an MR (the Home summary stands in meanwhile, with the description marked as still arriving) and `⠋ refreshing` once there is data to refresh. A failed read raises one pop-up for the whole outage, `Could not load api!1 · U retries`, and the tab says `✕ could not read the diff: the forge is unreachable` with `U tries again`. The screen carries a short cause (unreachable, token rejected, not found, rate limited, forge error, timed out), never the event id or the request URL; the full error is in the audit log (`mr.load`, `ade log`) and the inbox row's detail. A retry that fails again raises a new pop-up.
- **CI:** the pipeline as a station line in the repo's ink (`● build ━━ ✕ lint ──  ○ test`: passed stages filled, the first stage that has not passed ends the travelled line), then one row per job: glyph and word (`✓ passed`, `✕ failed`, `⟳ running`, `○ pending`, `– skipped`, `▸ manual`), name, stage, duration. `l` opens the job's log tail in a dialog; `r` retries the failed jobs.
- **AI keys** (only while AI is on): `A` runs the agent review pass over the whole MR from any tab and `P` is the agent menu (plan, address comments); on Threads `d` drafts a reply to the selected thread (it lands in the reply editor under a faint `AI draft · <model> · <cost> · edit it: enter posts, esc throws it away` line and is never posted by itself) and `s` summarises the thread (a `Summary` block above its conversation). A draft that finishes after the user left the thread waits behind a green `✓ AI draft reply ready · r opens it in the editor`. A call that needs a yes opens the **Ask dialog** (`Ask the model · agent review · api!2`: the reasons in amber, the pre‑flight line, `Nothing is sent until you say yes.`, `enter send · esc cancel`). **`D` on the Diff tab** opens the MR's diff in `delta` (else `$GIT_PAGER`, `core.pager`, `$PAGER`, `less -R`): in a zellij floating pane that closes with the pager, or, outside zellij, in this terminal while the dashboard steps aside.
- **Footer:** the tab's keys, then the page actions (`a approve · R ready/draft · m merge · S submit review`), then `tab`, `esc back`, `? keys`, then `A agent review` (AI on) and `P agents` (the item has a work item), then `tab`, `esc back`, `? keys`. On a narrow terminal whole hints drop from the end of the line, the way out and the help never.
- **Writes** (approve, ready/draft, merge, reply, resolve, retry, submit) run in the background, one at a time per MR. The strip shows the progress; the result arrives as a pop‑up and an inbox row (`mr.merge`, `mr.resolve`, `review.submitted`, … and `….failed` in red with the error as detail); the forge write is audited (`forge.*`).

### Review surface (Review tab, `c` on the Diff tab, `S`)

One surface for reviewing yourself and for triaging an agent's drafts. A comment is a **draft** until `S`; drafts live in the cache, so quitting loses none and `ade review add` drafts appear.

- **Draft block (under a diff line):** `✎ your draft · comment`, or `✎ agent draft · pending triage · y accept · n deny · e edit · ▲ blocking · long`, then the body wrapped behind the `┃` at the pane's width or 100 cells, whichever is smaller. A blocking draft reads `▲ blocking` in amber, the same mark as the Review list (the `▲` carries it under `NO_COLOR`). When the head does not fit (a narrow pane) its segments move to their own lines in the order who and state, severity and `long`, then the keys: nothing is cut mid-word, and the severity is never the part that goes. Denied drafts stay faint with `denied · never posted`. A body over 280 characters carries an amber `long`. Scrolling never opens a view on the tail of a block: it starts on the code line that owns it.
- **Agent pass line:** with AI on, the Review tab opens with one line: faint `A runs an agent review pass: its comments arrive here as pending drafts`; `⠋ agent review running` (the strip says `⠋ agent review…` on every tab; the page stays usable); green `✓ agent review done · 2 comments pending · claude-haiku-4-5 · $0.0021 · 1 dropped (not on the diff)`; amber `▲ agent review failed: …` or `▲ agent review waits for a yes`. The drafts it saved are the pending agent drafts below, triaged as usual; nothing reaches the forge. With `ai.mode = off` the line is absent: only `A` disappears.
- **Review list:** under the `Review` section rule (guide words: `4 drafts · 2 agent pending · 2 will be sent`), pending agent drafts first (they need you), then what will be sent, then denied. A row is the severity (`▲ blocking` amber, the rest plain; `comment` when none), `path:line` (`(removed)` for the old side) with an amber `long` after it when the body is over the house limit, and the right-aligned `agent · pending` (bold amber) / `you · accepted` / `… · denied`; that column ends on the section rule's right edge. The selected draft shows its body and, if pending, its keys. Accepting a pending draft moves it down, so the next one takes its place: `y y n y` triages a list.
- **Keys:** `y` accept, `n` deny (asks for an optional one‑word reason, kept in the audit log), `e` edit (an agent draft becomes accepted), `s` cycles severity, `Y` accepts all pending, `d` deletes your own draft, `enter` jumps to its diff line. `y`/`n`/`e` also work on the Diff tab for the draft under the cursor. Every decision is audited (`review.comment.accept|edit|deny|delete`).
- **Comment dialog (`c`):** the target line (`limit/token_bucket.go:3`, `(removed line)` on the old side) with the line's text behind a `┃`, severity chips (`[comment] blocking suggestion question nit`, `tab` cycles), the editor. `enter` adds the draft, `alt+enter` (or `ctrl+j`) is a newline. House style shows as the placeholder: one point, problem first, at most two sentences.
- **The editor** (every dialog with text: comment, edit, reply, deny reason, submit summary) is a bubbles `textarea`: soft-wrapped at the dialog width, up to five rows (then it scrolls with the cursor), no line numbers, prompt or painted background, a faint placeholder, the cursor a static reverse-video cell (it survives `NO_COLOR`). Keys: arrows and `ctrl+b/f/p/n` move, `alt+←/→` (or `alt+b/f`, `ctrl+←/→`) move by word, `home/end` or `ctrl+a/e` go to the line ends, `alt+<`/`alt+>` to the start and end, `backspace` and `ctrl+d` delete a character, `ctrl+w` or `alt+backspace` the word before the cursor, `alt+d` the word after, `ctrl+u` and `ctrl+k` to the line start and end, `shift+arrows` select. Bracketed paste inserts the text, newlines kept (the one-line Deny reason joins them with spaces). `enter`, `esc`, `tab` and `shift+tab` always belong to the dialog.
- **Reply dialog (`r` on Threads):** the thread being answered (`general · reviewer-rae: "Is a burst of 50 too high…"`) behind a `┃`, then the editor. `enter` posts at once, as a reply is not a draft.
- **Submit dialog (`S`):** `3 comments go out as one batch: one notification for the author`; an amber `▲ 2 agent drafts still pending · they stay drafts until triaged`; a faint `1 denied · never posted`; an optional summary editor; `[ ] also approve 7f6e5d4c` (`tab` toggles). Refuses when there is nothing to send, no summary and no approval.
- **Merge dialog (`m`):** `source → target`; the verdict (`✓ mergeable · head 7f6e5d4c is what you reviewed`, amber `▲ not mergeable yet: the pipeline is still running` when merge-when-pipeline-succeeds is possible, red `✕ cannot merge: …` otherwise); unresolved threads, approvals and CI; the options `[ ] s squash commits`, `[ ] d delete the source branch`, `[ ] w merge when the pipeline succeeds`. A refusal shows only `esc close`. The merge is pinned to the head the page showed.
- **Job log dialog (`l` on CI):** the tail of the log (last 16 KiB) in ADE's own ink (a bubbles viewport), scrolled to the end; `j/k` scroll, `h/l` sideways for long lines, `g/G` top and bottom, `pgup/pgdn` ten lines.
- **Editor:** a reverse‑video cursor cell (so it shows under `NO_COLOR`), soft wrap at word boundaries, `ctrl+w`/`ctrl+u`/`ctrl+a`/`ctrl+e`.
- **Dialogs** (reply, comment, edit, deny, submit, merge, job log and the page's help) take the Agent dialog's shape: one rounded box, at most 100 columns (full width below), centred and anchored at the top, on a blank field that replaces the tab while it is open, so no fragment of the Overview, Threads or Review text shows beside or below it (the field is deliberate: a dialog floated over a live body leaves mid-word fragments and orphan station rows). Bold title, a blank line, the content, a blank line, the key hints in the footer's style; the footer repeats the hints. Pop-ups are held back while one is open.

## Markdown and code

Issue and MR descriptions, the acceptance list, notes and AI summaries are markdown; they are rendered by glamour through `internal/mdrender`, in a style built from this theme, never from a stock glamour style.

- **No background, ever.** The ground is the terminal's. Headings and `**strong**` are bold (the title heading also underlined), `*emphasis*` italic, `~~strikethrough~~` crossed out, quotes and rules faint (`┃ ` / `│` quote marks, a `─` rule; ascii `| ` and `-`), links underlined with the address after them in faint (no hyperlink escape sequences are written: a web tty or multiplexer may print them), inline `code` between backticks, tables ruled with `│ ─ ┼` (ascii `| - +`), images as `[image: alt]`, HTML comments dropped.
- **Lists:** `• ` bullets (ascii `- `), `1. ` numbers, `[x] ` and `[ ] ` task boxes. A wrapped item hangs under its text.
- **Width-aware:** every line is at most the pane's width (a code line or table that is wider is cut into rows, never overflowing); trailing padding and runs of blank lines are trimmed.
- **Code blocks and the Diff tab** are highlighted by chroma (`internal/syntax`), by the fence's language or the file's extension: keywords bold violet, types and functions blue, strings teal, numbers and constants amber, comments faint grey italic. The red and green of the removed and added marks are never used for a token, so the `+`/`-` mark (coloured, bold under the cursor) stays the only red or green on a diff line; a file with no known language keeps the whole line in the mark's ink. Under `NO_COLOR` the output has no colour at all: keywords stay bold and comments italic, the `+` and `-` characters carry the meaning. Without `delta`, `D` writes the patch through chroma's diff lexer (added lines green, removed red, hunk headers blue, file headers bold) before `less -R`; a pager of your own (`$GIT_PAGER`, `core.pager`, `$PAGER`) or `delta` gets the plain patch.
- **NO_COLOR and ascii** both work by construction: the markdown style uses attributes only, so the only colour in it is inside code blocks.

## Do's and Don'ts

### Do:

- **Do** draw every new surface's progress or relationship as a station line (`●━━●━━◉──○`) in the relevant repo's ink.
- **Do** pair every state with a glyph and a word; test under `NO_COLOR=1` and `host.glyphs = "ascii"`.
- **Do** put scope and counts in guide words on section rules, not in separate headers.
- **Do** make overlays full‑width below 100 columns, so no cut fragments show around them.
- **Do** keep update and sync state in the header and notifications in pop‑ups; never block the list on the network.
- **Do** keep notifications inside the dashboard: no terminal escape sequences, no desktop notifiers.

### Don't:

- **Don't** paint a background colour or choose a font: the terminal's ground and face belong to the user.
- **Don't** use colour outside line inks and state marks (The Quarantine Rule).
- **Don't** put borders on the base layer. Borders mark overlays only.
- **Don't** truncate mid‑word without `…`. Wrap prose instead (The No‑Mid‑Word Rule).
- **Don't** record no‑op status (for example "all repos up to date") in the inbox. It is a toast.

## Budget page

`b` opens it from Home or Worktrees; `b` or `esc` returns to the page it was opened over, `L` switches to the Log, `t` still flips Home and Worktrees. It answers four questions in one scroll: how much of each cap is left, which profile is active and what its provider says, where the money went, and how the agent's review drafts fared.

- **Layout:** the Home pattern. At 100 columns or more the list takes 64% and the selection's details sit to the right behind a faint `│`; below that the list fills the width and `tab` swaps in the details. Every row is one line and selectable (`j/k`, `g/G`); the list scrolls to keep the selection in view.
- **Status line:** one faint line above the first rule says where the figures came from: `⟳ refreshing providers · figures as of 4s ago`, `provider figures as of 12s ago`, an amber `▲ stale: cached provider figures as of 3h ago · r reads providers now` (a profile whose read failed keeps its old snapshot; the age is the oldest figure on the page), a red `✕ no provider figure for gateway · r tries again`, a red `✕ refresh failed: …`, or an amber `▲ AI is off (ai.mode = off)`. With no figure read at all it says `figures not read yet`, never an age. The page paints from the ledger and cached snapshots at once; the provider read runs in the background and never blocks it. `r` reads the providers now.
- **Sections:** each opens with a section rule whose guide words carry the headline figures and drop whole groups from the right when they do not fit.
  - **Caps** (`day $0.38 of $2.00 · week $1.10 of $8.00`): one station line per cap, `●━━◉────○`, the baseline, the ground spent, the train where the spend stands, the cap at the end. The train reaches the end and the line turns red at the cap. Beside it, the share used and the state in a glyph and words: `✓ ok · $1.62 left`, amber `▲ near cap · $0.40 left` from 80%, red `✕ cap reached · calls stopped`, red `✕ over cap by $0.40 · calls stopped`. A cap that is not set says `no cap set`; a sprint cap with no sprint window says `no sprint known · U syncs to learn it` (the cap is then not enforced, rather than guessed).
  - **Profiles:** the active profile is the train `◉` with a bold `active`; the others are a faint `○`. The right of the row is the merged provider figure in words: `gateway $0.0080 of $0.01 · resets 12 Nov`, `moonshot $0.12 spent · balance $4.80`, a soft limit as `… of $5.00 soft limit`. A figure older than asked for adds amber `▲ stale · timed out`; a source that failed with nothing cached says `✕ no figure · key rejected`; a source not read yet says `not read yet`. The row carries only a short cause (timed out, connection refused, host not found, key rejected, read failed). The details list the per-role models, this week's ledger spend, the provider's scope, cap, remaining, window, reset and age, and its caveat; a failed read adds a red `✕ provider read failed: <cause>`, the full reason wrapped whole in faint, and what to do (`r reads the provider again`), and a stale one an amber caveat that the provider may be further along. Reasons are redacted; no credential is ever shown.
  - **By day / By feature / By model / Top items:** a spark bar of `━` cells scaled to the section's biggest bucket (`=` in ascii), the amount right-aligned, calls and cache hits faint. A day with no calls says `no calls`; today is marked `today`. `enter` on a top item goes to it on Home when Home knows it; otherwise it does nothing. With no calls at all the four collapse into one `Spend` rule and `no AI calls yet`.
  - **Recent stops:** `✕ stopped`, the time, the feature, the profile and the provider's or ADE's message; `✓ no budget stops` when there are none.
  - **Review triage:** per profile, `12 drafts · 58% accepted · 17% edited · 25% denied`, as shares of the drafts someone triaged, plus `· n pending`. Five or more triaged drafts with more than half denied add amber `▲ mostly denied`, so a noisy reviewer model shows.
- **Detail scroll:** a detail taller than the pane (a profile, below 100 columns especially) ends in a faint `↓ 6 more lines · J scrolls` row instead of silently clipping; `J/K` scroll it until the last line (the caveat, `as of`) is on screen, and moving the selection resets it.
- **Footer:** `j/k move   J/K detail   enter open item   r refresh providers   b back   L log   i inbox   ? keys   q quit`; below 100 columns `j/k move   tab details   r refresh   b back   L log   ? keys`, and with the details showing `j/k move   J/K scroll   tab list …`. A budget that cannot be read says `✕ could not read the budget`, the cause wrapped whole, and `r tries again`.

## Log page and History tab

`L` opens the audit log (PLAN 4.1); `L` or `esc` returns, `b` switches to the Budget. The History tab on the MR page draws the same entries for one item.

- **Log layout:** the Home pattern again: list left, the selected entry in full on the right, or one pane with `tab`/`enter` swapping in the details. The `Log` rule's guide words say how many entries show and the window (`8 entries · since 1d`); a narrowing filter adds `actions forge.*` and `matching "merge"`, and the count reads `1 of 8 entries`. Entries sit under a faint day sub-rule indented three cells (`Wed 11 Nov ── 5 entries`), newest first; when the window holds a single day the sub-rule is bare, since the `Log` rule already carries the count. An unreadable log says `✕ could not read the audit log`, the cause wrapped whole under it (a path breaks after a `/`, so `permission denied` is never cut off) and `r tries again`.
- **Row:** marker, the time, the actor (faint, dropped when the list is narrow), the action, the subject (the target, else the item, shortened like a ref), and the outcome at the right as a glyph and a word: `✓ ok`, red `✕ error`, amber `▲ cancelled`, faint `○ skipped`. A dry run adds `· dry run`. AI entries add the cost (`✓ ok · $0.0026`) or the words `cache hit`.
- **Filters:**
  - `/` opens an inline prompt in the footer (`/ text┃`); it filters as you type, over the action, target, item and error, ignoring case. `enter` keeps the text, `esc` restores the previous one, `ctrl+u` clears.
  - `a` cycles the action group: all, `forge.*`, `ai.*`, `review.*`, `budget.*`, `git.* project.*`, errors only.
  - `s` cycles the window: 1h, 1d (the default), 7d, all; it reads the log again. `c` clears the text and the group. The selection stays on the same entry when a filter changes and the entry is still listed.
- **Jump:** `enter` goes to the entry's target, else its item, when Home knows it. A work item or child issue selects its row on Home (a Home filter that hides it is cleared); an MR opens the MR page on that MR. Anything else (a path, a draft id, a command) shows its details instead.
- **Detail:** a bold action, the outcome glyph and word with the time, then every field the entry has behind faint 10-cell keys: id, actor, target, item, project, dry run, outcome, error (red), url. An entry with an ai block adds an `AI` heading and profile, driver, model, tokens in/out/cache, cost with its source, cache hit, artifact, destination host and bytes. Params follow, pretty-printed (already redacted when written); long values wrap, never cut, and a path wraps after a `/` rather than mid-word. A faint last line says what `enter` will do. `J`/`K` scroll a pane taller than the screen; a clipped pane ends in `↓ n more lines · J scrolls`. Below 100 columns the footer reads `enter go to item` (and `J/K scroll` while the details show).
- **History tab:** one line per entry, newest first: a faint relative time (`10m ago`, `3h ago`, `2d ago`, then the date), the outcome glyph, the action in words (`forge thread reply`), and right-aligned the outcome word with `· $0.0026` or `· cache hit` for `ai.*` entries. When there are more entries than lines the last line says `+n earlier`. An item with no entries says `No recorded actions on this item yet.`

## Agent dialog (`a` on a Home item, `P` on the MR page, `A` on Home for every run)

One rounded overlay, at most 100 columns wide (full width below 100), centred and anchored at the top so it does not jump between states, on a blank field that replaces the Home body while it is open (a deliberate choice: a dialog over a cut-off list leaves mid-word fragments), with a footer that says the dialog has its own keys for PLAN 6.6. It owns the keys while open (`q` closes it). It re-reads the run store whenever the cache changes (the dashboard's file watcher), so a run started here or by `ade agent` in another pane appears and moves on by itself. All agent, forge and git work runs in commands; nothing blocks the list beneath. `a` on the MR page stays approve and `A` there is the AI review pass, so the agent menu is `P` there.

- **Menu.** The item's title in faint, then two section rules:
  - `Start` (`work in the item's worktree`): `p plan` with `read-only: issue, comments, AGENTS.md`, and `c address comments` with `api!1 · 2 unresolved, replies drafted`. With no open MR that has unresolved threads the second row is faint and says why, and `c` says it again as an amber warning rather than starting anything. Home's `A` is the same list without `Start`, for every item, each row led by the item in its repo ink.
  - `Runs` (`5 runs`): one line each, newest first. Cursor `▸`, the state as glyph and word, the id, the kind, then at the right the spend against the cap and the time spent (`$0.07/$0.50 · 1m40s`).
- **State marks** (always glyph and word, so `NO_COLOR` and ascii read the same): `⟳ running`, `⟳ planning`, amber `▲ needs approval`, amber `◉ review`, green `✓ pushed`, red `✕ failed`, faint `· cancelled`; ascii `~`, `!`, `@`, `+`, `x`, `-`.
- **Plan review** (`enter` on a run that needs approval): a `Plan` rule with the run id, the spend so far and `awaiting your approval` (`approved` once it is), the plan text wrapped behind a faint `┃` and scrolled with `j/k`, `pgup/pgdn`, and a faint line with the worktree, driver and cap. `enter` approves; the same key then reads `run it in the worktree` and starts the implementation, and `i` (once approved) starts it on a separate `<branch>-ai` branch and worktree instead, so your own tree stays yours. Approving never runs by itself. `e` opens `plan.md` in `$EDITOR` (the dialog is suspended); editing after approval voids the approval, which the footer warns about. `x` discards the run.
- **Run page** (`enter` on any other run): a `Run <id>` rule with the kind and state, faint 10-cell keys (state, item, driver, cost against the cap, elapsed, MR, commits, drafted replies, one `call` row per agent process with exit, cost and turns, and a call stopped by ADE leads with red `✕ stopped at the cost cap`), a red error line, and for a run with changes a `Diff` rule (`3 files · +10 -0`) with one row per file: status letter, path, green `+n`, red `-n`. A run on a `-ai` branch adds a `-ai` row (`42-fix-ai in …/42-fix-ai · waits for accept or discard`; after accept an `accepted` row says the branch was fast-forwarded and is not pushed yet) and its hint row reads `a accept` and `D discard` instead of `P push`. Keys: `l` lazygit on the worktree (the `-ai` one while it exists; a floating zellij pane inside zellij, the terminal handed over otherwise), `a` accepts a `-ai` run in review (commits, fast-forwards the item's branch, removes the `-ai` worktree and branch; a branch that moved on is refused with the reason as a warning and nothing changes), `D` discards it after a `Discard` confirmation (`y` removes the worktree and branch, `n` backs out; the item's own branch is not touched), `P` push, `x` discards a run that has not finished (a failed, pushed or cancelled run has no `x`), `esc` back.
- **Push** asks first: `Push` rule, the file and line counts, `Commits everything in the worktree as the configured git user, marked (ade agent), then pushes <branch>. The merge request updates by itself.` `y` commits and pushes, `n` backs out. A run that is not in review refuses `P` with the reason.
- **Failures** are pop-ups (`agent <item>: …` through the notification centre) as well as a red row; a run that needs you raises one too (`plan needs your approval`, `ready for review`).


## AI digest and stand-in dialog (palette `:` on a Home item)

One rounded overlay on the Agent dialog's blank field, at most 100 columns, with its own key row (`j/k`, `pgup/pgdn` scroll, `esc` or `enter` closes). It opens from the palette entries "AI digest of new comments" and "AI stand-in description for an empty issue", on the selected Home item, and asks in a command: the list beneath never waits on the forge or the model.

- **Digest.** One section rule per place the item's comments live (its MRs, the tracker issue and each child issue): `ref title` and guide words `3 new comments since 12 Nov 10:00`, `… (first look)` or `no new comments since …`. Under a rule the digest is set behind a faint `┃` rail, then a faint line: `AI · <model> · $0.0012`, `cached, $0`, or `listed as they are: no model was asked` when AI is off. Opening it moves each item's local last-seen marker; opening it again shows only what came after. A call whose pre-flight needs a yes stops the dialog on the cost line with `y ask` and `n close`; sections already answered stay.
- **Stand-in.** Only for the item's issues whose description is empty. Each section's rule is labelled `AI stand-in description` and its text sits behind the rail under the same label, and the dialog ends with `local only: written from the title, never posted to the forge; the issue's description is empty`, so it cannot be taken for the issue's own text. With AI off the dialog says so and sends nothing; an issue that has a description reads `no stand-in needed`.
- Ascii and `NO_COLOR` read the same: the rails, `·` and `…` fall back with the glyph set, and every state has words.

## Issue overview pane (`ade item <ref> --watch`)

A live, read-only view of one work item for a narrow zellij pane (50–70 columns, 15–40 rows) next to the editor and the agent; it also runs standalone. It reads only the local cache and the item's record, follows them by itself (it re-reads within a fraction of a second of a cache or record write, by file watching; stat polling every 2 s where that is unavailable), and changes nothing. `<ref>` is the tracker issue, a child issue or an MR of the item. Off a terminal (`ade item <ref> --watch | cat`) the same view prints once, in plain text, at `$COLUMNS` (80 without it).

- **Header:** a bold `acme/tracker#15  title`, wrapped, the ref in the item's line ink. Then the item's station line from `domain.Stations` (the Home track: `●━━●━━●━━◉──○──○──○`, the train on the current stage, `◎` across repos, amber `◉`/`▲ blocked` when blocked) followed by the stage word in bold, and a faint legend of two-letter initials under the stations (`as st br dr ci rv mg`; one letter and one-cell connectors below 30 columns of content). Then `court · reason` as on a Home row: `you` bold, `▲ blocked` and `▲ waits` amber, other courts faint, a failed pipeline red with `✕`; a long reason wraps under itself, never cut.
- **Facts:** faint 10-cell keys, one row each: `weight` (`5w`, faint `unweighted`), `sprint` (`Sprint 42 · ends Fri 13 Nov · 3d left`, working days left in amber at one or none, only for the current sprint), `type` (`feature · api`, amber `▲ untriaged` / `▲ no type` / `▲ no app`), `workflow` (the label value, with an amber `▲ stage says …` on drift), `state`, `assignees`.
- **`Code` rule** (guide: `1 issue · 2 MRs`, or `not started`): per child issue a block behind a `┃` in the repo's ink: `api#3  title`, then for each of its MRs `!5 · open|draft|✓ merged 10 Nov · branch`, then glyph-and-word chips `✕ pipeline failed` (red, bold), `✓ pipeline passed`, `⟳ pipeline running`, `○ pipeline pending`, `no pipeline`, `✕ conflicts` (red, bold), `✉ 2 unresolved threads` (bold amber) or faint `no open threads`, `1/2 approved`, and the MR's URL on faint lines (wrapped after a `/`, never cut). A merged MR shows only its state. A child with no MR says `no MR yet`; no child at all says `no child issue yet`. MRs are filed under the child issue of their repo (by `#N` in branch, title or description when a repo has several children); one no child claims gets its own block headed `repo · no child issue`.
- **`Description` and `Acceptance` rules** (guide: `1/2 tasks`, `1/3 done`, from `itemdoc`): the description without its acceptance section, then the acceptance section. Both, and the notes under their rule, are rendered as markdown (see Markdown and code below): checkboxes read `[x]` and `[ ]`, bullets hang under their text, headings are bold, code fences are syntax-highlighted, runs of blank lines collapse. An empty description says `no description`; an acceptance-only one has no `Description` rule.
- **`notes` rule:** faint title, your notes from the record below it as written, or a faint `no notes yet`.
- **Footer:** faint `synced 4m ago   j/k scroll   r reload   e notes   q quit` (`never synced` before the first sync); keys drop from the right when the pane is narrow.
- **Scroll and clipping:** everything above the footer scrolls as one page. A page taller than the pane ends in a faint `… 12 more`, and after scrolling starts with `… 3 above`; `j/k`, `↓/↑` move a line, `pgdn/space`, `pgup` a page less one line, `g/G` the ends. There are no overlays and the mouse is left to the terminal, so text can be selected.
- **Refresh:** every two seconds the pane compares the size and modification time of `cache.db`, its write-ahead log and the item's record file, and reloads only when one changed, off the UI loop; `r` reloads at once. An item that leaves the cache keeps its last view with a faint `○ not in cache any more` under the header. An item not cached yet says `○ not in the cache yet` and fills in when a sync brings it. A failed reload is a red `✕ …` line above the footer and the old view stays.
- **`e`** opens the record at the notes in the configured editor, as `ade item --edit` does, and reloads when it returns.
- **Colour and glyphs:** state is always glyph plus word, so `NO_COLOR` and the ascii glyph set (`host.glyphs = "ascii"`) read the same; no colour outside line inks and state marks.

## Workspace tab (`w`, `W`, start work)

One zellij tab per worktree, generated KDL (internal/workspace/layout.go). Every dev layout has the same skeleton so the eye learns it once: the big **main pane** at the left (60%), and at the right (40%) the **overview** (40% of the column, `ade item <ref> --watch`, the Issue overview pane above) over a stack of **lazygit** (expanded) and a **shell**. Below, a strip (30% of the tab) with **one pane per task** of the workspace's own `run` group, side by side and titled with the node id (`web.dev`). Services that run elsewhere (other trees, `services.*`) start in a separate tab (below); with `services = "manual"` they stay in the strip as well.

- **Main pane:** `code` an editor, `agent` omp started with the ADE implement skill, `manual` a shell, `review` the diff through delta (the review tab carries no overview and no services). `w` opens with the default (`host.layout`, else the manifest workspace, else `code`), `W` with the other of editor and omp.
- **The strip holds the workspace's own tasks, and none starts on its own.** Each pane is a zellij command pane with `start_suspended`: it shows `Waiting to run: ade task run <node> …` and waits for Enter. Enter starts that node and what it requires (starting `web.dev` first brings `api.dev` up first); once running, the pane prints `ade: <node> runs in this pane · Ctrl-C stops it · Enter starts it again once it has exited`.
- **The services tab starts the services in the background.** The first time a workspace tab opens, ADE also creates an unfocused tab `<tab> · services` (you stay on the workspace tab). Its first pane runs the repos' `install` hooks (`ade ws install`); below it one pane per service of the run group (requirements running from other trees, and `services.*`) side by side in dependency order. Nothing is suspended: each pane starts at once and waits, without a prompt, for the install of its worktrees and for every service it requires to be ready. A required service with a `port` and no `ready` is ready once its TCP port accepts connections (the port gate); an explicit `ready` wins. A `services.*` instance another workspace already runs is reused, and its pane shows `already running (pid N)` and its log. `[workspaces.<w>] services = "manual"` opts out: no tab, the services join the tasks in the strip, waiting for Enter, with a first `services` pane whose Enter runs `ade ws up --no-zellij` for the whole run group (Ctrl-C stops what it started).
- **Chrome.** The tab is generated with zellij's standard `default_tab_template`: the tab bar on top (1 row) and the status bar below (2 rows) around the tab's panes, exactly like the session's other tabs; the session layout of the `ade` launcher (the borderless `home` dashboard tab) carries the same template. A layout without it gives the new tab no tab bar, so the session's other tabs seem to have vanished. Opening a workspace only ever adds its tab (or focuses it when it exists).
- A worktree that belongs to no work item (a baseline tree, named after the default branch) has no overview pane; the stack then fills the right column.
- Pane titles are the contract the proof script and the user both read: `agent` / `editor` / `shell`, `overview`, `lazygit`, `shell`, and the node ids.
