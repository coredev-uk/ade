# Changelog

## v0.2.0

The team's usage feedback: personal-namespace GitLab trackers, a safer workflow-label default, `ade gc` and `ade adopt`, project-wide services and install hooks, read and write tokens, project setup keys, new issue and MR commands, more AI helpers (research, MR descriptions, CI triage, comment digests, stand-in descriptions, `-ai` agent branches), an external notification command and a shell prompt segment. **Breaking:** an unset `labels.workflow.sync` now means `ask`, not `auto`; set `sync = "auto"` in the manifest to keep the old behaviour (see "Breaking default" below).

- **`ade issue child <tracker-ref>`** creates just the child issue of a tracker issue in a code repo (copied type, assignee, milestone and iteration, `relates_to` link, hierarchy parent), and **`ade issue assign <ref>`** assigns an issue to you, keeping the others (`--replace` for only you). Both are audited, take `--dry-run` and `--json`.
- **`ade mr checkout <ref>`** checks an MR's head out as a detached `mr-<iid>` worktree without a review tab; `--json` gives the path.
- **`ade mr from-branch [dir]`** opens the draft MR for the branch checked out in a worktree started outside ADE: MR template, `--closes`, commit prefix and quick-action stripping as for `ade start`.
- **`ade mr pipeline <ref>`** shows the MR's pipeline and jobs (failed first, with stage and duration); `--log <job>` prints a job's log tail.
- **`ade cleanup <ref>`** cleans up one item: removes its worktrees, fast-forwards the default-branch baseline and deletes the local branches, only where `ade gc` would remove the tree (clean, pushed, MR merged or closed). Dry run, `--json`, audited.
- **External notifications:** `[notify.external]` hands events to a command of yours (a CDE inbox, a webhook script): the event as JSON on stdin and `ADE_EVENT_*` variables, filtered by kind and minimum severity (default `budget.*` and `sync.stalled`, `warn`), killed after a timeout, deduplicated per kind, project and severity across processes (default 1 h), and never blocking the dashboard. Failures go to the audit log (`notify.external`), not the screen. `ade notify test` tries the command. A sync that fails for longer than `notify.sync_stalled_after` (default 2 h) raises `sync.stalled`, once per outage.
- **`ade prompt`:** a shell-prompt segment with the worktree's ticket and the count of items waiting on you (`GL-412 !3`), read from git files and the cache with no network, no git process and nothing written. It prints nothing outside ADE trees, takes `--format`, `--scope` and `--json`.
- **VS Code notifications extension:** not built; docs/PLAN.md says why and what covers it (`[notify.external]`, `ade inbox --json`, `ade prompt`).
- **Node working directory and prepare step:** a task or service takes `dir` (relative to the worktree root, validated to stay inside it) and `prepare` with `prepare_if_missing` (run a command such as `npm ci` only while a path such as `node_modules` is missing). `ade task run`, `ade ws up`, the zellij panes, the services tab and the VS Code `tasks.json` run the node in its `dir`; each prepare command is audited as `git.hook` with `hook=prepare`. The manifest schema and docs list the keys.
- **Project-wide services:** `ade services status|up|down|install|open` runs and inspects a project's services outside any worktree: status across every worktree (`--json`), start or stop named nodes or groups over the baseline trees (instances are shared with workspaces; `down` leaves what a workspace holds unless `--force`), and a standalone `<project> · services` zellij tab. `ade task run --project <name>` is the pane command.
- **AI research, MR descriptions and CI triage:** `ade ai research <issue> [--detach|--show]` runs a stored, detached research job per issue (state in the item's record, answer cached so it is never bought twice, a notification when done; `R` on Home); `ade ai describe <mr> [--apply]` drafts an MR description from its template, commits and diff, previews it and writes it on confirm (audited as `forge.mr.description`; `B` on the MR page); `ade ai ci-triage <mr>` gives a cause and a fix for each failed CI job from its log tail (`t` on the CI tab). All follow the pre-flight, caps, cache and AI-off rules; GitLab only for the description write.
- **Breaking default:** an unset `labels.workflow.sync` now means `ask`, not `auto`. ADE no longer moves labels on a shared board unless the manifest says `sync = "auto"`. With `ask`, `ade start` moves the label only with `--move-label` or the dialog toggle, and `ade sync` reports pending moves as warnings and in the inbox. `ade project bootstrap` writes `sync = "ask"`.
- **Personal namespaces:** GitLab trackers in a user namespace sync. Capabilities skip the group endpoints and sample the tracker project, so weights go to the weight field. Sprints come from the tracker project's milestones. `ade doctor --probe` agrees with sync, and the sprint-move hint names the project.
- **`ade start --dry-run`** accounts for the workflow label: the move as a write step, or a note saying why it will not happen.
- **`ade gc`** keeps a branch without an upstream unless HEAD is the head of one of its MRs or sits on a remote branch that still exists after a fetch. A local branch as upstream does not count as pushed, and an unreadable worktree status keeps the tree. The dry run says why each tree counts as pushed.
- **`ade adopt`** brings an existing branch, local or from another clone (`--from`), into the layout and writes the `ade.*` worktree keys, with no forge writes.
- **`ade items --json` and `ade item`** list each item's worktrees: path, branch, dirty, ahead and behind.
- **Agents** run with `ADE_AGENT_RUN=1`, in `ade agent` runs and in the zellij agent pane, so a global `pre-push` hook can stop an agent's own push (sample in docs/manifest.md). Agent prompts carry the expanded commit prefix.
- **Baseline folder:** the docs and the remaining code paths use the folder named after the default branch (`develop/`, not always `main/`).
- **Names:** people show as `Name (username)` in the dashboard, MR page, overview, item records, notifications and `ade mr`.
- **Sprint list:** it holds only sprint tickets whose tracker issue has no assignee, and shows each ticket's author. A ticket assigned to someone else reads `assigned to <name>`, not `unassigned`. Assignment matches by user ID first.
- **My work:** a code-repo issue appears under its tracker item when they are tied by GitLab's work-item hierarchy, a `Parent:` line or a `relates_to` link, even when the tracker item is not yours or is outside the sprint window. `ade start` also sets the hierarchy parent when GitLab allows that pairing, and warns without failing when it does not.
- **AI answers** cut at the output limit are retried once with a larger limit. If still cut, they show a note and are not cached. Classify, sprint-parent and thread summaries have larger limits, and their old cached answers are renewed.
- **Weight suggestion** ranks closed issues by the shared title words that matter (inflected stop words no longer match), takes the score-weighted median of the five nearest, says when only one issue matched, and lists the matches with their weights.
- **Bare `ade`** lands on the dashboard: it focuses (or recreates) the `home` tab of the `ade` session, also when run inside zellij.
- **Install hooks:** `[repos.<r>.hooks] install` runs once per worktree (again when the commands change, or with `ade ws install --force`), inside the repo's dev shell.
- **`ade start --branch <repo>=<branch>`** (and `b` in the start dialog) pins a sibling repo to a named branch: an existing branch and its MR are reused, a new name is created. The dry run notes the branch per repo.
- **AI answers cut short** show a note beside the text, never inside it, so a draft reply or a parsed answer never contains it. The same prompt is not re-bought for 30 minutes unless you refresh, and the pre-flight shows the retry's worst case. Summaries, draft replies, standups and sprint reviews are renewed once.
- **Project dotfiles:** a `[dotfiles]` table in the manifest names the team dotfiles repo (the one used with `coder dotfiles`). `ade setup` and `ade dotfiles` clone or update it and run its install script, or symlink its dotfiles into `$HOME`, as Coder does. Inside Coder they skip a repo Coder already applied. `[dotfiles]` in the user config can switch it off or point elsewhere, and `ade doctor` reports it.
- **Classify and weight** work on app-repo issues and closed issues, skip a project whose manifest cannot be read, and show the real error when the issue cannot be read.
- **Facets from the parent:** an app-repo issue or MR without its own type, apps or weight takes them from its tracker issue, on Home rows, review rows and the detail pane.
- **Several MRs on one issue:** the item focuses on its open MR (the least advanced when several are open). It is listed first, so the MR page and overview open on it. The side panel shows the open MRs, with a count of earlier merged or closed ones, and reads CI and review from the focus MR. `w` opens its worktree, `ade start` resumes its branch instead of the alphabetically first one, and `ade items --json` reports it as `focus_mr`.
- **Last working day:** with AI set up, Home opens with a short AI summary of your last working day: the last day you pushed commits or opened or merged an MR, whatever the calendar says. It is split into Shipped, In progress, and Reviews and discussion, and skipped when the budget is critical (90% of a cap) or the call needs confirmation.
- **Retro:** the Sprint review page writes its AI narrative when it opens, under the same rule. The narrative is a structured retro: outcome, a timeline of what landed in date order, carried over, and velocity.
- **Reviews** no longer list draft MRs. A draft marked ready appears then.
- **Notes on work:** `ade note <ref> <text> [--blocked]` and `N` on Home add a dated local note (never sent to the forge). The side panel shows the newest three, and a row whose newest note is blocked is marked.
- **CI job log** fills the screen, reads the last 512 KiB, and searches with `/`, `n` and `N`.
- **Sprint review** with several projects opens on the first project with sprints instead of failing. `p` switches projects; the CLI says which project it chose.
- **Background services:** opening a workspace for the first time also opens an unfocused `<tab> · services` tab. It runs the install hooks first, then each service in dependency order, with no "waiting to run" panes. A required service with a port and no `ready` check counts as ready when its port accepts connections. `[workspaces.<w>] services = "manual"` keeps the old on-demand strip. A waiting pane reports every 30 seconds and stops with the reason when its dependency or the install failed, or after `--wait-timeout` (10 minutes by default). A lockfile change at the worktree root reruns the install.
- **Read and write tokens per forge:** `read_token_env` / `read_token_cmd` name a read-only token. Syncs, dashboards, AI context, `doctor --probe` and git clone/fetch use it; forge writes and `git push` use `token_env` / `token_cmd`, resolved only on the first write (a forge with only a read token is read-only through the API). Agent runs and the work tab's agent pane start without the write token's variable. `ade doctor` checks both tokens, warns when the read token can write and fails when the two belong to different accounts; `ade init` and `ade setup` take `--read-token-env` / `--read-token-cmd`.
- **`ade config check --manifest` without a user config:** a manifest can be validated before `ade init` or `ade setup` ran; its `forge` name, which only a user config resolves, is a warning instead of an error, and a user config that fails to load is reported as a warning.
- **`ade setup` registers new `--project` / `ADE_SETUP_PROJECT` manifests** when a config already exists (appended like `ade project add`, only after the token check), so a manifest added to a Coder template reaches existing workspaces; `--json` lists them as `registered`.
- **`commit_prefix` `{child}` without a child issue** uses the leading number of the branch (`57-fix-export` → 57) before falling back to the tracker iid, for MRs opened in a code repo without a child issue; applies to agent commits, start work, the worktree's `ade.commitPrefix` and squash messages.
- **`ade cd <ref|repo> [--repo <name>]`** prints the item's worktree path (or a repo's baseline) and nothing else on stdout, offline, for `adecd() { d=$(ade cd "$@") && cd "$d"; }`.
- **`conventions.mr.reviewer_group`** requests review from a group when start work opens the MR: the GitLab group's active members (you excluded; GitLab Free keeps one) or a GitHub team. The dry run and the start dialog show who, and a group that cannot be read only warns.
- **Project-wide setup (`[project]` in the manifest):** `agents` writes `<root>/<project>/AGENTS.md` and adds it to the implement skill and agent prompts; `packages` (+ `nixpkgs`) generates `.ade/shell` and puts the packages on PATH around every pane, task and service of the project. `ade project status` shows them and `ade setup --warm` pre-builds the shell.
- **Repo groups (`[repo_groups.<name>]`):** display-only groups that `ade project status` lists repos under; a group with `workspace` gets `<root>/<project>/<workspace>.code-workspace` with its repos' baselines, and `ade vscode workspace --group <name>` regenerates it or limits an item's workspace to the group.
- **Agent runs on a separate branch:** `ade agent run <run> --ai-branch` implements on a new `<branch>-ai` branch and worktree, so your own tree stays yours (it may be dirty, and you may keep committing). `--background` starts that run detached. When it is in review, `ade agent accept <run>` fast-forwards your branch to the result and removes the `-ai` branch (it refuses, changing nothing, when your branch moved on), and `ade agent discard <run>` throws the `-ai` branch away. Neither pushes. In the agent dialog `i` runs an approved plan on a `-ai` branch, and `a` and `D` accept and discard it.
- **AI digest of new comments:** `ade ai digest <ref>` summarises only the comments that arrived on an MR or issue since you last looked, then moves a local last-seen marker kept in the item's record. Nothing new costs nothing. With AI off or `--no-ai` it lists the new comments. The palette (`:`) opens it on a Home item.
- **AI stand-in description:** `ade ai standin <issue-ref>` writes a short stand-in for an issue with an empty description, from its title, labels and linked issues. It is marked as a stand-in, kept only in the item's record, cached, and never posted to the forge. The palette (`:`) shows it for a Home item's empty issues.

## v0.1.0

First release. ADE is a terminal dashboard and CLI that replaces the GitLab web workflow (GitHub for personal projects), built around zellij.

- **Home:** your work items as station lines (assigned → merged) with court, reason, weight and sprint load; reviews requested, sprint, next and previous sprint; search, command palette, filters, activity, notes, weights, classify, move to the next sprint.
- **Start work and the work tab:** child issue, branch, draft MR and worktree in the chosen repos, then a zellij tab with your editor, a shell or an omp session carrying the issue, a live issue overview, lazygit and service panes you start on demand (dependencies first, `API_URL` wired). `v` opens a multi-root VS Code workspace for the project.
- **MR page and review:** overview with AI summary, threads, highlighted diff, CI; reply, resolve, approve, ready, merge; line comments and agent review drafts sent as one batch.
- **Agents:** plan, approve, run, review in lazygit, push, within a per-run cost cap; transcripts stay in the item record.
- **Agile:** standup and sprint review by count and weight (unweighted never counts as 0), velocity, burn-down, cycle time, optional AI narrative.
- **AI and budget:** omp, Anthropic and OpenAI-compatible drivers (LiteLLM gateway with a classification model role), result cache, ledger over the audit log, caps and pre-flight, budget and log pages.
- **Setup:** `ade init`, `ade project bootstrap` (manifest from a forge group), `ade setup` for Coder startup scripts, self-hosted GitLab (custom CA, path prefix, SSH port, version gating), headless CDEs (VS Code remote CLI, web tty).
- **Notifications** live inside the dashboard only: pop-ups, a notification centre, unread count and row markers.
- **ade-nvim:** an isolated Neovim with the snacks.nvim picker (`nix run github:coredev-uk/ade#ade-nvim`).

Install: `nix profile install github:coredev-uk/ade`, or download a release archive. Setup guide: [docs/setup.md](docs/setup.md).
